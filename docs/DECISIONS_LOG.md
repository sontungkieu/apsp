# Decisions log

Engineering decisions taken within the scope of the Research Spec / Implementation Guide v1.1.1. None of them
changes the scientific configuration (grammar, reward, scoring path, seed scheme, split, caps, thresholds or
paid-information rules). Where a choice can affect numerics, it is part of the EPH body, so banks/costs made
under a different choice cannot be mixed silently.

| # | Date | Decision | Why / effect |
|---|---|---|---|
| D1 | 2026-10-14 | **Ownership adjustment.** For this round Claude Code implemented the GPU modules *and* the modules the guide assigns to Codex (contracts, data, sim, policies, stats, reports). | The user authorised it explicitly. No Codex code existed in the workspace (fresh repo), so nothing was rewritten. Codex can review and take over these modules; interface changes from now on go through QUESTIONS/DECISIONS with a version bump. |
| D2 | 2026-10-14 | The engine drives the diffusers components **step by step** (`apsp/gpu/engine.py`) instead of calling `FKDStableDiffusion.__call__`. | The online controller has to regain control every Δ=4 forwards, and the pipeline call has no hook for that. Per-forward math is the same as the pinned base loop (scale_model_input, CFG chunk order [uncond; cond], `DDIM.step(eta=0)`). `collect_bank --test-equivalence` measures the difference against the reference pipeline (pending GPU run). |
| D3 | 2026-10-14 | The prompt is encoded **once (batch 1)** and the embeddings are tiled to k rows. | Every candidate gets bit-identical conditioning, which replay needs (candidate independence). The base encodes a k-prompt list as a batch instead. Equivalence variant B measures that effect. |
| D4 | 2026-10-14 | Initial latent: CPU `torch.Generator(seed)`, **float32** `randn(1,4,64,64)`, then cast to the UNet dtype; `init_latent_sha` hashes the cast bytes. | `apsp-v1-sha256-cpu` fixes the seed and the CPU generator but not the draw dtype; float32 is the portable choice. |
| D5 | 2026-10-14 | The hook reads `pred_original_sample` from the **same** forward. The base collector recomputes x0 with an extra UNet forward; we never do (M0 counts UNet calls = 64). | Guide CC-2. The reference recomputation exists only inside `reference_psp.py` as a diagnostic. |
| D6 | 2026-10-14 | PRUNE keeps survivors in their **old row order**. The base `run_psp.py` reorders rows by rank. | Spec §5.1. Under candidate independence the result is the same; it keeps RowMap/CFG gathers simple to audit. |
| D7 | 2026-10-14 | Grammar state after PRUNE: `fresh` stays True and `pruned=True`, so CONT is the only legal action left at that checkpoint. | This follows directly from the action table (no VERIFY while fresh, no second prune at the same j). |
| D8 | 2026-10-14 | Synthetic fixtures use split names `syn_train_fit`, `syn_train_dev`, `syn_eval`. | Keeps the PREREG split guards strict: a synthetic bank can never unlock `train_fit`/`val`/`test`. |
| D9 | 2026-10-14 | Signed-PREREG marker format is `docs/PREREG_SIGNED/PREREG-<X>.json` with `role: research`, `signed_by`, `proposal_path`, `proposal_sha256`. | The guard also checks that the approved proposal file has not changed. No code writes these markers. |
| D10 | 2026-10-14 | `schedule_cost`: scheduled methods pay no dispatch fee; every query pays `ver[k]` even without a cut; a pred cut pays `lfeat+pred+prune` without `ver`. | Spec §7.1 and Guide §6.3. Cross-checked against the closed form C(j1,j2) for all 105 pairs. |
| D11 | 2026-10-14 | ImageReward is loaded through the **official** `ImageReward.ImageReward` class with an explicit missing-key check (the base uses `strict=False` without checking). | D12 | 2026-10-14 | `weights_variant: null`, i.e. the fp32 safetensors cast to fp16 at load, as the base does. | Same numerics as the base. The `fp16` variant files are a different artefact and would change the EPH. |
