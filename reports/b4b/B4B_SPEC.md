## Grid

- **Definition.** k_init ∈ {16,12,8,4,3,2,1}; 1–4 cutoffs from steps {4,…,60}. Keeps strictly decrease and are
  taken from the same set, below k_init. PSP's budget filter is Σ particle-steps ≤ best_of_n × T = 256.
- **Size.** **7,823 strategies.** By k_init: 16 → 1,988; 12 → 2,504; 8 → 2,366; 4 → 815; 3 → 135; 2 → 15;
  1 → 0 (it needs a cut).
- **Check.** The enumeration in `apsp/sim/b4b_grid.py` is identical, in order, to PSP's own `enumerate_strategies`,
  run on the pinned file.

## Mapping to this project

| PSP | Here |
|---|---|
| cutoff step t (of 64) | checkpoint j = t / 4. All cutoffs are multiples of 4, so j ∈ 1..15: **every checkpoint is on the bank** |
| seed window of logical seed 0 (k_init seeds) | first k_init CandidateIds of pool 16: (0,0)…(0,7),(1,0)…(1,7) |
| rank by guidance metric at the cutoff, then seed | preview IR at j descending, then CandidateId ascending |
| final pick: metric at step 64 among survivors | delivered IR among the final survivors; fin(final_k) charged |
| budget = particle-steps only | project ledger: den(k) per interval, paid VERIFY ver(k) at every cutoff, prune(k→k′), fin(final_k). PSP's filter defines the grid; caps decide feasibility |

- **No auxiliary bank or online path is needed for replay.** A cutoff that is not a multiple of 4 would raise
  `OffBankCheckpoint`; it is never rounded.
- **Online B4b.** Runs use batch sizes 16/12/8/4/3/2/1 (native batching). Replay of B4b is therefore approximate
  after the first prune, like every pruning method (Amendment 1).
